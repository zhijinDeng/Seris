# 生产决策保障合同

## 定位

知质·灵巡是MES/QMS/SCADA与现场岗位之间的质量风险决策保障层。合同约束数据如何进入、结论如何形成、动作由谁执行、异常时如何降级以及事件如何关闭。当前仓库实现脱敏仿真、可执行事件准入、关系图查询和Base写入回读；任务与文档为对象样例。生产部署需要将相同合同落实到服务端策略、企业身份、OT分区和不可变审计。

## OT与IT边界

| 区域 | 主要对象 | 允许方向 | 禁止动作 |
| --- | --- | --- | --- |
| OT控制区 | PLC、机器人、SCADA、检测设备 | 向边缘区发布只读点位 | 数字员工直接写控制参数 |
| 边缘区 | 采集、特征、store-and-forward | 向工业DMZ发布签名事件 | 无身份设备接入、越点位采集 |
| 工业DMZ | Broker、Schema、隔离区、Outbox | 向IT应用区发布受控事件 | IT应用直连PLC |
| IT应用区 | 知识图谱、GraphRAG、策略、审计 | 写MES协同状态与飞书对象 | 绕过质量放行与审批 |
| 飞书协同区 | Base、任务、卡片、Aily、文档 | 回传任务和签署状态 | 在消息卡片内直接执行最终放行 |

## 事件数据契约

边缘事件按`data/factory_event.schema.json`的2.1契约准入，必须包含`source_system`、`source_event_id`、`event_time`、`ingest_time`、`sequence_no`、`asset_id`、`station_id`、`tag_id`、`unit`、`quality_code`、`calibration_id`、`calibration_valid_until`和`object_binding`。运行脚本执行空值、重复、水位、单位、工艺窗口、校准有效期和质量码检查；不满足阈值的事件进入`QUARANTINED`，不能触发自动派单。决策快照保存原始样本SHA-256。

决策快照必须包含`rule_set_version`、`feature_schema_version`、`knowledge_snapshot`、`ontology_version`、`evidence_hash`、Top-3、冲突证据、干预状态和运行模式。事件护照的哈希输入随干预、签署、授权和关闭状态变化。

## 服务端状态机

主状态为`OBSERVED → QUALIFIED → REASONED → DISPATCHED → CONTAINED → VERIFIED → APPROVED → CLOSED`。异常分支包括：

- `QUARANTINED`：数据质量不合格。
- `HUMAN_REVIEW`：低置信、证据冲突或知识不可用。
- `EXPANDED_SCOPE`：复检不合格，需要扩大VIN/批次范围。
- `OUTBOX_PENDING`：协同接口失败，等待幂等补偿。
- `REJECTED_CLOSE`：关闭证据、角色或签署不满足策略。

任何状态变化保存前后状态、操作者、角色、时间、规则版本、原因和证据ID。前端只展示服务端结果，不以浏览器变量作为生产授权。

## 失效与恢复

数据延迟超过业务窗时冻结新增派单和关闭；图谱不可用时切换规则与控制计划只读包，不输出唯一根因；模型不可用时保留硬规则、影响圈定和人工任务；飞书不可用时写入Outbox，保存尝试次数、回执和下次重试时间；网络恢复后按事件ID和平台事件ID去重，只补偿一次。

备份范围包括事件Schema、规则、特征、知识快照、索引、审批和审计。生产试点必须明确RPO/RTO，完成恢复演练后才能进入L3。恢复过程不得删除原审计记录。

## 验收

1. 删除硬编码前置量后，四场景仍能由时间序列复现18至46分钟结果。
2. 至少一例干预使原Top-2上升为Top-1，且事件护照同步变化。
3. 干预缺实测、准则或签署时，物理复检门和关闭动作均被阻断。
4. L0、数据过期和知识失效能在策略层阻断规定动作。
5. 飞书中断时任务显示待补偿，恢复后同一幂等键只创建一次。
6. 已关闭P1五项门完整率为100%，过程字段完整率不低于95%，越权成功操作为0。
7. `scripts/test_event_contract.py`必须拒绝缺字段、重复、延迟、错误单位、校准失效和可疑质量码六类异常。
8. 试点统计、金标准、置信区间与Go/No-Go遵循`docs/pilot-acceptance-protocol.md`。
