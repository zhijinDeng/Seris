# 答辩演示路线

这份原型不定位为完整生产系统，而是用来证明方案的关键闭环：现场异常如何被AI数字员工感知，如何通过知识图谱与Graph RAG形成证据链，如何把处置动作推送到飞书，最后如何沉淀为复盘知识。

## 3分钟演示顺序

1. 打开 `app/index.html`，先看左侧异常事件流，选择 `E-20260717-001` 总装拧紧异常。
2. 看中间证据链：总装一线、底盘合装、TQ-17拧紧枪、扭矩偏低、预紧力不足，说明Graph RAG不是只检索文本，而是沿设备-工艺-质量关系追溯。
3. 看右侧飞书任务看板：AI把处置建议拆成可执行任务，并标注风险等级、影响VIN范围和待确认状态。
4. 看下方飞书集成动作：展示多维表格记录、机器人卡片、Aily追问提示词和复盘回写。
5. 运行 `python scripts/run_quality_agent.py`，证明异常评分、案例召回、证据链和处置建议不是静态文案。
6. 运行 `python scripts/feishu_client.py --event-id E-20260717-001 --write-preview`，证明可生成飞书多维表格与Webhook payload。

## 评委应看到的能力点

| 能力点 | 演示位置 | 说明 |
| --- | --- | --- |
| 智能制造知识底座 | `data/quality_ontology.jsonld`、证据链节点 | 定义设备、工序、参数、报警、缺陷、根因、任务等核心类 |
| 从感知到行动 | `run_quality_agent.py`、前端任务看板 | 异常进入后自动输出风险、根因、处置、飞书任务 |
| Graph RAG推理 | 前端证据链、案例召回 | 通过图谱关系与历史案例约束生成，降低幻觉 |
| 飞书协同 | `feishu_client.py`、飞书集成动作面板 | 支持多维表格记录、Webhook卡片、Aily追问 |
| 可解释闭环 | `data/end_to_end_trace.json` | 每一步都有输入、证据、动作和复盘输出 |

## 演示结论

平台只是“可视化外壳”，核心价值在于它把质量管控从被动告警变成了主动数字员工：能发现异常、解释风险、组织证据、推动任务、沉淀知识。
