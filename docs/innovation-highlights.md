# 评委眼前一亮的创新点

## 1. 从“质量问答助手”升级为“主动巡检数字员工”

常规方案往往是工程师提问后，AI再去查文档。本方案反过来：AI数字员工持续监听工艺参数、设备报警、质检结果和维修状态，主动发现隐性质量风险。它的工作方式更接近一名在线质量工程师：先发现异常，再解释风险，再推动处置，而不是等待用户提问。

**亮点表达：** 不是“人问AI答”，而是“AI主动找问题、带证据找人闭环”。

## 2. 质量因果图谱：不只连知识，而是连“风险传导路径”

传统知识图谱容易停留在实体关系展示。本方案把设备、工位、参数、质量特性、缺陷模式、根因、控制计划和处置任务连接成质量因果链。例如“拧紧枪TQ-17 -> 扭矩偏低 -> 预紧力不足 -> VIN隔离 -> 复检扭矩 -> 套筒更换”。这让AI输出不再是泛泛建议，而是沿制造过程可追溯的证据路径。

**亮点表达：** 不是普通知识图谱，而是“设备-工艺-质量-处置”的风险传导图。

## 3. Graph RAG证据合约：每条结论必须带三类证据

为了降低大模型幻觉，Agent生成任何P0/P1建议前，都要满足“证据合约”：至少包含实时参数证据、图谱路径证据、历史案例或控制计划证据。没有证据链，就不能自动升级风险或创建高风险处置任务。

**亮点表达：** AI不是直接给结论，而是先交付“证据链合约”。

## 4. 飞书不是通知工具，而是质量闭环执行系统

飞书在本方案中不是最后发一条消息，而是作为质量协同执行层：Aily负责解释和追问，多维表格负责事件、证据、任务、复盘结构化，Webhook负责快速播报，SLA字段负责催办，任务关闭后再回写复盘知识。

**亮点表达：** 把飞书从“消息群”升级成“质量问题闭环操作系统”。

## 5. 人机共治安全闸：高风险动作必须人工确认

制造现场不能让AI直接停线、批量返工或修改设备参数。本方案设计了P0/P1人工确认门：AI可以定位风险、生成证据、建议隔离范围、创建待确认任务，但停线、批量隔离、参数改写等动作必须由质量负责人确认。这样既体现自主性，也符合工厂安全治理。

**亮点表达：** AI自主思考，但关键动作有权限边界和审计留痕。

## 6. 质量记忆飞轮：每次异常都会反哺FMEA和知识图谱

很多AI系统做完一次分析就结束。本方案把每次处置结果沉淀为复盘知识：最终根因、有效措施、误报原因、漏报原因、预防规则都会回写知识图谱、历史案例库和FMEA条目。越用越懂产线，越用越能提前预警。

**亮点表达：** 不是一次性AI分析，而是会成长的工厂质量记忆。

## 7. 影响范围计算：从“发现异常”到“锁定VIN”

现场质量管控最怕只知道有问题，却不知道影响哪些车。本方案把异常时间窗、工位、设备、VIN流转、批次和工艺参数关联起来，输出建议隔离范围。评委能直观看到：AI不是只报“扭矩低”，而是能定位“VIN尾号8123-8125需要复检”。

**亮点表达：** 从报警点位走到VIN级影响范围。

## 8. 一键生成“三张卡”：风险卡、证据卡、任务卡

演示时可以强调：一次异常进入系统后，AI会自动生成三张卡：

| 卡片 | 内容 | 价值 |
| --- | --- | --- |
| 风险卡 | 风险等级、影响范围、疑似根因 | 让负责人快速判断严重性 |
| 证据卡 | 参数越界、图谱路径、历史案例、控制计划 | 让建议可解释、可审计 |
| 任务卡 | 隔离、复检、校准、维修、复盘 | 让处置进入飞书闭环 |

**亮点表达：** 把复杂质量分析压缩成可执行的三张卡。

## 最推荐在答辩中重点讲的3个创新

1. **主动巡检数字员工**：区别于普通问答助手。
2. **Graph RAG证据合约**：区别于容易幻觉的文本RAG。
3. **飞书闭环执行系统**：区别于只做展示看板的平台。
