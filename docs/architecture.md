# 技术架构

## 本体设计

核心类：车型、零部件、工序、工位、设备、工装、传感器、工艺参数、报警、质量特性、缺陷模式、根因、控制计划、处置任务、复盘知识。

核心关系：位于、监测、属于、偏离、可能导致、由检测验证、由控制计划约束、由任务处置、复盘为知识。

## Graph RAG流程

1. 事件标准化：把设备报警、参数波动、视觉检测结果转为统一QualityEvent。
2. 子图召回：按设备、工位、参数、质量风险召回2-3跳邻域。
3. 文档召回：检索FMEA、控制计划、维修手册、历史质检报告。
4. 证据排序：优先使用同车型、同工位、同参数、近30天高相似案例。
5. 推理生成：输出风险等级、影响范围、疑似根因、处置建议。
6. 规则校验：对停线、批量隔离、返工等高风险动作加入人工确认。
7. 结果沉淀：处置结果写回图谱和复盘知识库。
