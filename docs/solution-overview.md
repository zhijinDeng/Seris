# 整体解决方案书

## 一、方案总览

“知质·灵巡”是一名面向赛力斯超级工厂的设备质量风险主动管控数字员工。方案以工厂质量知识底座为根，以GraphRAG和因果约束为推理引擎，以Autonomous Agent为工作流中枢，以飞书Aily、多维表格和机器人卡片为协同执行层，形成从感知到行动的闭环。

围绕题面要求，方案的建设顺序是先建“设备与质量知识底座”，再做“会主动思考和执行的Agent”，最后用“飞书协同工具链”把风险处置落到人、车、设备和任务上。三者缺一不可：没有知识底座，数字员工无法解释；没有自主Agent，系统仍停留在问答；没有飞书闭环，推理结果难以转化为现场行动。

它要解决的不是单点报警展示，而是现场质量管理中最难沉淀的隐性风险：设备已经出现退化或偏移，但终检尚未报废；工单虽然显示关闭，但故障原因、处置措施和失效模式仍未形成可复用知识；点巡检标准没有随重复失效动态更新；跨系统标识和时间口径使设备异常难以映射到质量影响。知质·灵巡把这些碎片组织成一条可追溯风险线程。

赛事提供的脱敏快照包含625类设备、9,673个设备实例、336项设备功能、1,287条失效模式和406张故障工单。383张工单可关联设备，但仅71张关联失效模式，62张形成设备类别一致的完整结构链。该数据说明首期应先做好对象对齐、工单知识化和闭环质量审计，再逐步叠加实时OT参数与VIN影响圈定。

## 二、总体架构与核心模块

1. 现场与边缘层：只读接入PLC/SCADA设备告警、工艺参数、MES过站、QMS缺陷、视觉/X光、点检和维修数据。

2. 事件与数据质量层：按2.1 Schema校验来源、序列、时钟、单位、设备/工位/点位ID、校准有效期和VIN/批次绑定，不合格事件进入隔离分支。

3. 知识底座层：以“设备类别—设备实例—设备功能—失效模式—故障工单”为企业数据主链，扩展点巡检标准、维护计划、复机确认、工位、工序、参数、质量特性、VIN/批次、角色和任务。

4. 风险检测层：组合工艺窗口、EWMA、CUSUM、响应残差、同位复现、设备寿命和知识关系，计算缺陷显性化前置量并识别P1/P2/P3。

5. GraphRAG与因果保障层：当前作品以36个图谱节点、32条关系边和来源轨迹验证两类机制，包括四类时序异常和一类企业数据“闭而未解”审计；生产版接入企业图数据库、文档切片与向量索引，输出Top候选、冲突证据和反证动作。

6. Agent与策略层：执行观察、研判、检索、推理、行动和复盘，控制运行模式、职责分离和五项独立关闭门。

7. 飞书与治理层：以六张关联表、任务、卡片、Aily、原生审批、文档和事件订阅承接协同；P1不允许数字员工自动放行，L3不由浏览器授予。

## 三、关键业务流程

企业数据旗舰案例首先处理“闭而未解”。脱敏实例EQ-XBB841ED4011在快照中关联121张安全防护报警工单，其中119张显示已关闭，但120张原因未确认、121张均未关联失效模式。数字员工沿“设备实例—设备类别ET-X23C58B2E6F0—安全防护功能—两条维护因素失效模式”检索，并反查同类别实例EQ-X97058A25213的4张已关联工单和清洁疏通或润滑处置。系统据此建立P2知识债务事件，但不自动确认根因，而是派发夹持元件、执行元件和安全回路检查，组织设备、维修、质量三方确认，再发起点巡检项目、检测方法和维护周期变更审批。

以总装底盘合装拧紧为例，TQ-17智能拧紧枪出现M12关键螺栓扭矩偏低。系统不是只展示报警，而是自动完成六步：

1. 识别86.4N·m低于92-108N·m工艺窗口，并发现连续3辆车同点位越界。
2. 通过MES过站记录圈定VIN尾号8123-8125，并向上一次合格校验时间窗扩展核查。
3. 沿“总装一线-底盘合装-TQ-17-扭矩参数-预紧力风险-FMEA条目-历史案例C-009”路径检索证据。
4. 结合角度补偿波动、套筒寿命、校准记录和历史案例，形成“套筒磨损叠加校准漂移”的根因假设。
5. 自动生成车辆隔离、扭矩复检、设备校准、套筒检查、备用设备首件确认和FMEA回写任务。
6. 当复检合格、设备恢复、责任人确认和放行依据齐全后关闭事件，沉淀为下一次推理样本。

## 四、创新点

设备质量风险线程：把报警、参数、VIN、证据、任务、责任人、SLA和复盘结论绑定成一条业务对象，避免质量知识散落在系统、群聊和个人经验里。

主动式GraphRAG：不是人员提问后再检索，而是在参数流和告警流中触发检索；图谱决定检索范围，文档补足证据，规则和因果约束校验推理方向。

闭而未解审计：把“已关闭”与“已解决”明确区分。系统持续检查工单集中与复发风险、原因缺失、泛化处置、失效模式空链和点巡检更新滞后，主动发起知识债务事件。

一车一因果链：把一车一档从追溯档案升级为风险推理载体，让每辆受影响车辆都能说明“经过了哪个工位、受到哪个参数影响、依据哪些证据执行了哪项处置”。

飞书即执行层：飞书不只是通知渠道，而是质量事件、任务、责任、状态和复盘的协同载体。Aily承接查询和更新，多维表格承接结构化闭环，机器人卡片推动班组响应。

质量知识受控学习：关闭事件只有在根因、措施、复机确认和有效性观察齐全，并通过业务审核后，才沉淀设备—症状—根因—措施关系；模型建议不能直接改写失效模式和点巡检标准。

## 五、落地路线

第1阶段：离线回放。导入历史异常、维修、检测和放行记录，验证风险分级、影响范围圈定和根因命中率。

第2阶段：影子运行。系统在当班实时生成建议，但不改变现有放行流程，记录质量工程师采纳、修改或驳回原因。

第3阶段：协同闭环。接入飞书多维表格和机器人卡片，实现P1/P2事件任务派发、状态跟踪和关闭回写。

第4阶段：产线复制。把四类工况模板扩展到电驱装配、电池包气密、整车标定、供应链来料和路试问题闭环。

## 六、业务价值与验收

首期目标为：关键异常定位时间下降40%-60%；P1事件任务派发小于1分钟；根因Top-3命中率达到80%以上；关键工序追溯覆盖达到100%；重复质量问题下降15%-25%；复检、维修、放行和复盘记录结构化率达到90%以上。收益核算只统计被现场采纳并完成闭环的事件，保证价值口径可验证。

## 七、生产级组件与接口设计

数据接入采用事件总线和批流结合方式。高频设备参数先在边缘侧完成窗口、漂移、连续性与缺失检查，只把异常片段和特征送入风险层；MES、QMS、维修和文档数据按事件ID与时间窗关联。所有输入记录source_system、event_time、ingest_time、version和quality_flag，防止用过期数据解释当前异常。

知识底座采用“本体层—实例层—证据层”三层结构。本体层定义设备、工位、工序、参数、质量特性、缺陷模式、控制计划、VIN/批次、角色和任务；实例层承载实时设备与事件关系；证据层保存文档片段、规则版本、历史案例和人工确认。GraphRAG先执行子图扩展和规则剪枝，再按关系距离、时间一致性、数据质量和案例相似度重排证据，最后交给大模型生成带引用解释。

Agent由观察器、风险评估器、检索器、影响圈定器、任务编排器、关闭校验器和知识回写器组成。每个工具只获得完成岗位动作所需的最小权限，P1关闭工具必须接收质量负责人确认令牌。任务与Base写入使用事件ID幂等，事件订阅用message_id、event_id和task_guid去重，避免网络重试造成重复任务或重复关闭。

## 八、飞书执行织网

当前在线Base已建立13个质量事件字段，并完成写入回读核验。任务GUID `f10d51e5-cc8e-4c71-9441-cd29a77feacf`与复盘文档token `PjludNq8foBhkrxV8VQccsldneb`作为对象样例保留；企业身份、角色映射和编排回执完成前，不将对象样例计为生产自动闭环。

企业设备数字化管理平台继续作为设备类别、实例、工单、失效模式、点巡检和维护标准的主数据系统，飞书不复制也不替代主档。飞书侧设置设备风险事件、跨专业诊断任务、质量影响确认、复机审批、标准变更申请和复盘知识六类协同对象；Aily提供设备风险查询、闭而未解审计、失效模式确认和复盘入口。审批通过后由服务端连接器按版本与幂等键回写设备平台，记录、任务与审批事件再驱动Base状态更新。

## 九、可靠性与安全

系统采用三类降级策略。数据降级：关键点位缺失、时钟偏差或延迟超阈值时只保留监测，不生成处置任务。模型降级：置信度低或证据矛盾时输出待核查项，不给出单一根因。流程降级：飞书不可用时生成本地事件包并进入人工任务清单，恢复后按幂等键补偿同步。

系统不存储飞书明文密钥，不在公共仓库提交访问令牌；VIN和人员信息按企业数据分级策略脱敏。所有根因结论保留证据来源、模型/规则版本、操作人和时间戳。质量负责人保留最终处置与放行权，AI的岗位价值是缩短信息收敛和协同时间，而不是取消质量责任制。

## 十、决策保障、责任链与推广合同

方案将“确定性”拆成三道关口。决策前检查数据完整、时序先行、机理一致、同位复现和干预可证伪；现场处置关闭前检查源数据、范围、物理复检、授权确认、任务完成与知识草案入审；知识债关闭再检查标准审批、主平台回写和有效性观察。生产实名身份、量具、附件和审批回执由服务端及企业应用回读。

运行模式由策略服务统一约束：影子验证为L0只读，不能派单或关闭；协同执行为L2，可写飞书对象但不能写PLC和执行质量放行；生产受控为L3，经企业审批后可写MES协同状态，仍须人工放行。数据延迟时冻结派单，图谱不可用时切换规则只读包，飞书中断时进入Outbox并按事件ID幂等补偿。

跨线推广复用事件模型、Agent状态机、权限矩阵、飞书字段、审计规范和指标口径，仅替换感知适配器、工艺本体、规则包、案例集和物理验证方法。新工序必须具备稳定对象ID、事件时间、明确质量特性、可执行复检方法和责任岗位后才能准入。
