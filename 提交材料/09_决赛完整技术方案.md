## 二、整体概述：在既有数智质量基础上补齐主动行动层

赛力斯正在推进“产业大脑+超级工厂”引领的智能制造2.0和数智质量2.0。公司2025年年度报告进一步披露工业AI大模型、行业首创智能连接工艺系统和36,000+质量点位全自动实时监控，并以“信息—决策—行动”闭环连接生产、质量与供应链；2024年ESG报告披露超过30,000个过程质量自动化控制点、1,200余个AI质量监测点，并建立“一车一档”和“一件一档”；2025年半年度报告披露关键生产工序、焊点质量和整车静态质量的高度自动化检测基础。企业真正需要补齐的已不是“有没有数据”，而是弱信号如何形成可行动风险、跨系统证据如何收敛、处置责任如何流转、关闭结果如何成为下一次判断依据。

知质·灵巡不重复建设采集系统和质量看板，而是在MES、QMS、SCADA/PLC、检测系统、维修系统和一车一档之上建设质量风险决策保障层。数字员工按照“主动发现—证据推理—受控执行—确定关闭—知识回写”循环值守：先从连续时序和设备状态中发现尚未显性化的质量风险；再以知识图谱约束GraphRAG检索范围，形成Top-3候选根因、支持证据、冲突证据和反事实动作；随后通过飞书把隔离、复检、维修和首件确认分配到具体岗位；最后只有在客观复检、实名确认和审计回写完整时才允许关闭。

方案的企业价值不是“多发告警”，而是把每一次异常组织为一条可核验的设备质量风险线程：同一事件ID贯穿原始信号、设备与工位、VIN或零件批次、规则和知识版本、根因假设、干预结果、责任任务、复检实测、授权签署、PFMEA/控制计划变更及有效性观察。

## 四、四步可信闭环

### 1. 早发现：从越界报警升级为缺陷显性化前风险

边缘侧先执行时间戳、采样率、缺失率、量纲、量程、校准状态和VIN/批次绑定检查。通过数据质量门后，工艺硬规则守住安全底线，EWMA识别均值小幅漂移，CUSUM积累持续偏差，指令—反馈残差识别执行机构退化，设备寿命和知识关系提供业务约束。只有统计检测器至少一项触发、知识关系命中且能够圈定影响对象时，系统才把弱信号升级为可行动风险线程。

前置量按`T_downstream - T_actionable`计算。`T_actionable`为时序检测与知识关系首次形成最小证据共识的事件时刻；`T_downstream`为现行下游质量门理论可检出的时刻。前置量由时间序列实际计算，不从文案读取。脱敏总装案例中，EWMA于14:08发现偏移，14:16形成可行动共识，14:38为下游理论显性点，计算前置22分钟。

### 2. 能证伪：从相关性线索升级为可干预假设

生产版GraphRAG先在图谱中锁定设备、工位、参数、质量特性、失效模式、PFMEA和历史案例，再检索SOP、维修记录、控制计划和历史8D。当前仓库完成了可运行的机制原型：28个实例节点、24条关系边，按事件ID执行有界关系路径检索，输出6步查询轨迹、来源片段和原始样本哈希；企业文档切片、向量索引和图数据库属于现场接入项。输出始终保留稳定编号H1/H2/H3，并以Rank单独表达排序，避免干预后假设身份漂移。

决策前五项因果护栏分别为：数据来源和版本完整；原因信号在时间上早于质量偏离；关系符合设备与工艺机理；同设备、同工位或同批次可复现；干预结果能够增强、削弱或重排假设。互动工作台可执行两类反事实动作，干预结果会实际更新Top-3后验排序。缺少干预或物理复检证据时，关闭按钮保持禁用。

### 3. 有人负责：从一个确认按钮升级为岗位责任链

数字员工只负责发现、收敛、解释和编排，不掌握最终放行权。质量工程师确认风险受理与隔离范围；检测人员提交复检项目、实测值、量具和校准状态并签署检测结论；设备或工艺工程师提交纠正措施与恢复后首件记录；质量负责人审核证据并决定放行、扩大范围或升级。每次操作记录人员身份、岗位角色、时间、审批范围、意见和附件。

飞书承担协同执行而非控制设备。多维表格保存统一事件和证据记录，任务中心承载责任人、SLA、子任务、评论与附件，消息卡片用于接单和补充证据，Aily提供事件查询与复盘入口，事件订阅回收任务状态。系统不直接修改PLC/SCADA参数，不替代质量放行，不自动关闭P1。

### 4. 可复制：从单场景应用升级为质量能力资产

推广复用六类共用资产：事件数据契约、Agent状态机、人机权限矩阵、飞书字段、指标口径和审计规范。每条新工序只配置五类场景资产：感知适配器、工艺本体模块、规则包、案例集和物理验证方法。复制对象不是页面，而是一套能够通过相同验收合同的质量风险闭环。

## 五、整体架构与核心功能模块

系统采用七层架构。

1. 现场与边缘层：以只读方式接入PLC/SCADA、传感器、视觉/X光、设备点检和MES过站数据；完成窗口特征、时间同步、质量码、断点续传和本地缓冲。
2. 事件与数据质量层：统一事件时间、采集时间、序列号、源系统、Schema版本、单位、校准ID、缺失率、时钟偏差和VIN/批次绑定；不合格数据进入隔离区，不参与自动派单。
3. 质量知识底座层：以产品—过程—资源为主骨架，关联过程功能、质量特性、失效后果、失效模式、失效原因、预防控制、探测控制、S/O/D、行动优先级、特殊特性、控制计划、历史案例和责任角色。
4. 风险检测层：组合硬规则、EWMA、CUSUM、响应残差、设备寿命和图谱关系，输出弱信号时刻、可行动时刻、检测共识、风险等级和影响对象。
5. GraphRAG与因果保障层：沿图谱生成受约束检索子图，整合结构化事实和文档证据，形成Top-3、冲突证据、反事实动作及后验更新。
6. Agent与策略层：执行观察、研判、检索、推理、行动、复盘状态机；策略服务判断运行模式、岗位权限、数据质量和关闭条件，模型不能绕过硬规则。
7. 飞书与治理层：通过Base、任务、卡片、Aily、文档和事件订阅完成协同；统一保存规则集、特征Schema、知识快照、证据哈希、审批记录、Outbox补偿和审计日志。

生产网络采用OT控制区、边缘区、工业DMZ和IT应用区分区。现场数据通过受控通道向上发布，数字员工到PLC的控制写入路径固定阻断；受控执行仅表示可写入MES协同状态和飞书任务，不表示具备设备控制或质量放行权限。

## 六、知识底座与GraphRAG

### 1. 本体范围

知识底座至少包含设备、工位、工序、工艺参数、质量特性、车辆、零件批次、缺陷模式、PFMEA、控制计划、检测方法、量具、维修记录、证据、干预、任务、审批和复盘。PFMEA不保存为单一“根因文本”，而是拆解为过程功能与要求、失效后果、失效模式、失效原因、预防控制、探测控制、特殊特性、严重度、频度、探测度和行动优先级。

### 2. 图谱检索过程

事件首先按设备ID、工位ID、工艺参数和时间窗生成事实子图；再向质量特性、失效模式、PFMEA、控制计划和历史案例扩展；文档检索只在该子图约束的实体、版本和时间范围内进行。最终证据包同时保留原始点位、派生特征、关系路径、文档段落、版本、时间戳和证据哈希，避免模型脱离现场关系自由生成。

### 3. 双重确定性机制

决策前校验解决“这个根因是否值得行动”：检查数据完整、时序先行、机理一致、同位复现和干预可证伪。关闭前校验解决“这次事件是否可以结束”：检查影响范围锁定、物理复检通过、授权人员确认、责任任务完成、知识与控制文件回写。两组校验目的不同，任何一项失败都不能由模型置信度替代。

## 七、核心创新：自主数字员工、反事实干预与策略运行模式

数字员工设有三种模式。

| 模式 | 权限 | 外部写入 | 使用阶段 |
| --- | --- | --- | --- |
| 影子验证 | L0只读 | 不写入 | 历史回放、误报标定、规则与模型对比 |
| 协同执行 | L2建议+派单 | 写Base、任务和文档 | 试点运行，不触碰设备控制和质量放行 |
| 生产受控 | L3受控执行 | 写经审批的MES协同状态和飞书对象 | 完成安全评审、角色映射和服务端策略部署后启用 |

Agent状态机为`OBSERVED → QUALIFIED → REASONED → DISPATCHED → CONTAINED → VERIFIED → APPROVED → CLOSED`。状态不可跳跃。数据质量失败进入`QUARANTINED`，低置信或证据冲突进入`HUMAN_REVIEW`，复检不合格进入`EXPANDED_SCOPE`，接口失败进入`OUTBOX_PENDING`。P1事件必须经过风险受理、检测证据签署和最终授权三类责任节点。

## 八、飞书在线闭环

飞书能力按证据分为三层：质量事件Base写入与回读已经在线核验；责任任务和复盘文档提供可打开的对象样例；机器人卡片、Aily、企业角色映射、原生审批和事件消费者待企业开发者应用部署。生产数据模型为质量事件、处置任务、复检记录、设备维修、审批记录和复盘知识六张关联表，页面按同一事件ID展示六对象闭环，不把对象样例表述为现网自动编排。

1. 多维表格：统一事件ID、设备工位、VIN/批次、Top-3、证据链、干预结果、运行模式、事件护照、状态和关闭依据。
2. 任务中心：按质量、检测、设备、工艺和班组角色分派任务，记录SLA、附件、评论、驳回与完成状态。
3. 消息卡片：在责任群中呈现P1/P2风险、隔离范围和待办动作，支持接单、补充证据和升级，不在卡片内直接完成最终放行。
4. Aily：支持按事件ID、VIN、设备和时间窗查询证据链、当前责任人、未满足关闭项和历史同类问题。
5. 云文档与知识库：生成结构化复盘、PFMEA/控制计划变更草案和有效性观察记录，变更仍由授权岗位审核发布。
6. 事件订阅：监听任务和多维表格记录变化，用事件ID和平台事件ID去重，回写Agent状态机。

接口采用Outbox/Inbox和事件ID幂等。飞书不可用时事件包写入本地Outbox，记录重试次数、下次重试时刻和失败原因；恢复后补偿同步，不重复建单。消息发送保留显式确认门，避免演示数据触达真实组织。

## 九、完整案例：22分钟如何转化为受控质量行动

### 1. 场景

总装GA-12底盘合装工位的TQ-17智能拧紧枪用于M12关键螺栓。工艺窗口为92-108N·m，脱敏序列最终值为86.4N·m，影响VIN尾号8123-8125。

### 2. 主动发现

14:02建立稳定基线；14:08 EWMA首先识别均值偏移，但未立即派单；14:16 CUSUM、连续VIN、设备关系和PFMEA关系形成4/4共识，风险线程进入可行动状态；14:18出现硬阈值越界；14:38为下游质量门理论显性点。由时间戳计算前置量22分钟。

### 3. 影响圈定

系统从MES读取过站记录，以最后合格校验点、异常时间窗和设备恢复点为边界，锁定8123-8125三辆车。每辆车分别保存过站时间、设备与程序版本、实测参数、隔离状态和复检任务；复检不合格时按相邻时间窗向前扩展，全部合格时收敛范围。

### 4. 根因与反事实

初始Top-3为：套筒磨损叠加校准漂移86%，螺纹摩擦系数批次异常57%，程序或配方错配34%。Top-1有同点位复现、角度残差和历史案例支持，但存在“套筒账面寿命尚未到阈值”的冲突证据。

执行“更换套筒+标准件复校”后，标准件扭矩回到99.1N·m，角度残差收敛至基线，后验排序更新为93%、31%、14%。该结果增强设备侧原因，但不能代替三辆车复检。另一条“交叉换枪复拧”路径可用于区分设备侧原因与零件批次效应。

### 5. 协同与关闭

质量工程师确认风险受理和三辆车隔离；设备工程师校准TQ-17并检查套筒；检测人员按控制计划提交复检实测、量具ID和校准状态；班组长完成备用设备首件；质量负责人审核全部证据。关闭后系统生成PFMEA/控制计划变更草案和有效性观察任务，不自动发布控制文件变更。

## 十、四类工况模板

| 工序 | 主动信号 | 图谱主链 | 反事实动作 | 确定性验证 |

### 2. 脱敏仿真结果

总装、焊装、涂装和压铸四场景的缺陷显性化前置量分别为22、31、18和46分钟。每个数值均能追溯到`T_actionable`和`T_downstream`两个时间戳及完整检测轨迹。仿真不代表赛力斯现网收益，也不用于宣称真实召回率或缺陷下降。

### 3. 90天现场实测目标

| 指标 | 目标 | 计算与验收 |
| --- | --- | --- |
| 前置量中位数 | 不少于10分钟 | 已采纳事件的`T_downstream-T_actionable`中位数 |
| P1召回率 | 不低于95% | 被识别P1/现场确认P1，按周盲测 |
| 误报率 | 影子期不高于15%，协同期不高于10% | 被驳回且无须处置事件/全部可行动风险 |
| 根因Top-3命中率 | 不低于80% | 最终复盘根因是否进入首次Top-3 |
| 影响范围准确率 | 不低于90% | 正确圈定对象/最终确认影响对象 |
| 异常定位时间 | 下降40%-60% | 与人工跨系统查询基线对比 |
| P1派发时长 | 小于1分钟 | 可行动时刻至任务成功回执 |
| 已关闭P1五项门完整率 | 100% | 任一缺失即不计入关闭 |
| 过程记录字段完整率 | 不低于95% | 全部事件必填字段完整率 |
| 重复问题 | 下降15%-25% | 同设备/同失效模式复发率前后对比 |
| 越权操作 | 0 | 审计日志中的未授权成功操作数 |

所有业务收益只统计被现场采纳并完成确定性关闭的事件。每项指标报告样本量、点估计和95%置信区间，并按工序、班次、设备新旧与风险等级分层；金标准由双专家独立标注、第三人仲裁。P1重大漏判、越权成功或五门缺失仍关闭时立即No-Go。详细签收规则见`docs/pilot-acceptance-protocol.md`。

## 十二、落地可行性：90天实施路径与验收门

### 1. 第1-30天：数据与知识准入

完成总装拧紧和焊装点焊点位清单、事件Schema、时钟同步、数据质量规则、PFMEA/控制计划映射和岗位权限矩阵。退出条件为关键字段完整率不低于95%、VIN/批次绑定可追溯、规则与知识版本可回滚、OT只读通道通过安全评审。

### 2. 第31-60天：影子运行与标定

历史回放和在线影子模式不写外部任务。以现场最终结论为金标准，评估前置量、P1召回率、误报率、Top-3命中率和影响范围准确率。连续两周超过停用阈值时回退规则和模型，不进入协同执行。

### 3. 第61-90天：协同闭环

启用飞书Base、任务、卡片、Aily和事件订阅，仍不触碰PLC控制和最终放行。验证风险受理、检测证据、设备恢复、最终授权、Outbox补偿和有效性观察。达到全部关闭门和安全指标后，形成跨工序复制资产包。

### 4. 停用与回退条件

核心点位延迟超过30秒、VIN绑定失败、时钟偏差越界、规则/知识版本不一致、P1连续漏报、飞书写入与任务状态不一致时，停止新增自动派单并进入人工模式。规则、知识和特征Schema保留现行版与上一稳定版，回退过程记录审批人、原因和版本哈希。

## 十三、可靠性、安全与灾备

1. 数据延迟：标记证据过期，冻结新增推理，保留已验证硬规则和P1隔离。
2. 图谱不可用：切换控制计划与规则只读包，不输出唯一根因，生成现场排查清单。
3. 模型不可用：保留规则判定、影响圈定和人工协同，停止生成自由文本结论。
4. 飞书不可用：写本地Outbox并按事件ID幂等补偿，台账、任务和文档分别记录提交与回执状态。
5. 网络中断：边缘侧store-and-forward，恢复后按序列号重放，乱序事件进入隔离队列。
6. 越权操作：服务端策略校验身份、角色、工位、审批范围和双人复核，拒绝结果写入追加式审计。
7. 灾备：备份事件契约、规则、知识快照、索引、审批和审计数据，明确RPO/RTO并定期执行恢复演练。

治理框架参考NIST AI RMF的Govern、Map、Measure、Manage持续循环；OT网络与恢复参考NIST SP 800-82 Rev.3；制造实体和功能分层参考ISO 23247；设备、物料、人员与企业/控制系统语义交换参考OPC UA for ISA-95。

## 十四、落地可推广性：跨产线复制合同

新工序进入平台必须满足五项准入：存在稳定的对象ID和事件时间；能够映射质量特性与失效模式；有明确的物理复检方法；责任岗位和放行边界清楚；能够形成至少一组历史回放基准。接入后复用事件模型、状态机、权限、飞书字段、审计和指标，只新增点位映射、本体子图、规则参数、案例与验证动作。

首批四工序成熟后，可复制到电驱装配、电池包气密、整车标定、供应链来料和路试问题闭环。例如电池包气密只需替换压力衰减适配器、密封失效本体、泄漏规则和氦检/保压验证方法；任务、审批、证据护照和关闭门保持不变。
